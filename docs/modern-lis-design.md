# Modern LIS interface

The interface follows `Modern-List-Design`: navy navigation, warm off-white workspace, purple actions, white cards, serif headings and compact monospace labels. The supplied folder remains a reference; the application does not import its sample records or statistics.

## Shared styling

- `frontend/src/theme.css` contains the colour and typography tokens, shared component styling, sidebar layout and responsive rules. Change the `--lis-*` tokens to update the interface consistently.
- `frontend/src/App.tsx` renders the sidebar and page header around the existing screens. Navigation still follows the signed-in user's permissions. Hospital branding uses `/config`; the user name and role use the existing authenticated session.
- Fonts are bundled locally through Fontsource packages; the deployed UI makes no Google Fonts requests.
- Screen styles are separated from report print rules. The sidebar and page header are hidden when printing. Mobile report previews use a stacked footer and scrollable investigation tables.

## Data and workflows

Registration, patient search, sample acceptance, result entry, authorization, reports, catalogue, staff administration and exports retain their existing APIs. No database migrations, new data sources or design-folder records are added.

The sample cards count orders returned by `/worklist` for the current filters. Loading or failed requests show a dash; a successful empty response shows zero. The sample table shows an explicit failure state instead of displaying old rows after a failed refresh. No instrument utilization, turnaround-time metrics or live-sync claims from the reference are displayed.

## Verification

Run the frontend build with `npm.cmd run build` from `frontend`.

From `backend`, run:

```powershell
node test/revision-browser.mjs
node test/hospital-lookup-browser.mjs
node test/theme-browser.mjs
```

Browser scripts use Playwright from `PLAYWRIGHT_MODULE_PATH` or the existing local fallback documented in each script. The theme check covers seven routes at 320, 390, 768, 1024 and 1440 pixels, visible navigation, API-derived counts, loading/error/empty states, doctor navigation, sign-out and the print shell. Screenshots and a print PDF go to ignored `backend/test-results/`.

These browser checks intercept API requests with test-only fixtures. They do not create users, patients or orders in the application database, and do not establish live database workflow coverage.

To update the local Docker frontend while keeping the other services running:

```powershell
docker compose build frontend
docker compose up -d --no-deps frontend
```

The pre-existing `lis-release` package and image archive are separate distribution artifacts and are not regenerated by this UI change.

During local deployment, Nginx rejected the existing `listen 80 ssl` directive because no certificate was configured. `docker/nginx.conf` now uses `listen 80`, matching the Compose port mapping and HTTP health check. HTTPS termination still requires a separately configured gateway.
